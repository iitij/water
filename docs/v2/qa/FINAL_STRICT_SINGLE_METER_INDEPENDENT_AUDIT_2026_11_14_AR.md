# تقرير المراجعة المستقلة الأخيرة: العداد الواحد الفعلي وحذف الآثار القديمة

**التاريخ:** 14 نوفمبر 2026  
**المستودع والفرع:** `5krm/water` / `main`  
**الخلاصة:** **تثبّت التصميم وقيد التفرد واختبارات التكامل، لكن لا توجد شهادة صحة 100% أو قبول إنتاجي**. المراجعة كشفت مخاطر إضافية، وأصلحت ما أمكن إثباته آلياً، وفتحت مهاماً للباقي.

## 1. قرار التصميم الذي راجعناه

- لكل مشترك **صفر أو سجل عداد فعلي واحد كحد أقصى**؛ `inactive` لا يفتح خانة لعداد ثان.
- يُحذف العداد الزائد أو السابق في الاستبدال فعلياً، مع بياناته المرتبطة، **دون سجل عدادات تاريخية**.
- لا يحذف التنظيف بيانات المشترك العامة بلا علاقة بالعداد السابق، ولا بيانات المشتركين الآخرين.
- المزامنة المؤجلة لعداد قديم لا يجوز أن تُسند قراءتها للعداد الجديد.

## 2. نتائج مثبتة من الشيفرة والاختبارات

| المجال | الفحص | الحالة |
| --- | --- | --- |
| تصميم MySQL | فهرس `UNIQUE(subscriber_id)` بدلاً من فهرس العداد الحالي الافتراضي | نجاح آلي |
| ترحيل البيانات السابقة | حساب آخر عداد صالح وحذف بقية الصفوف التابعة، بما فيها SoftDeletes، مع تدقيق `water:audit-single-meter` | نجاح على قاعدة CI مؤقتة |
| استبدال العداد | عملية حذف القديم وإنشاء البديل مع معرّف جديد، ورفض قراءات البديل القديم | نجاح Laravel |
| البيانات المالية | إزالة قيود وفواتير وسندات العداد القديم مع حماية العمليات العامة وسندات مشترك آخر وتحديث مجاميع الصندوق | نجاح Laravel |
| الحذف المباشر والجماعي | حذف بلاغات وزيارات العداد المهمل مع إبقاء منع حذف العدادات ذات المعاملات المالية من مسار الحذف العادي | نجاح Laravel |
| Flutter / SQLite | إزالة العداد القديم محلياً، بما فيها حالة الخادم الذي يعيد قائمة فارغة، وعدم مسح النتائج خارج التصفية | نجاح Flutter |
| مزامنة الحسابات | منع عرض أو إعادة إرسال أو مسح عمليات حساب آخر، ومنع إعادة عملية أجنبية عند تصادم UUID | نجاح Flutter |
| قراءة API أثناء الاستبدال | إعادة فحص وتسجيل القراءة داخل `DB::transaction` بقفل `lockForUpdate()` على صف العداد | نجاح الاختبار المتسلسل؛ اختبار التزامن الفعلي متبقٍ |
| قراءة Filament أثناء الاستبدال | إعادة الحارس والحساب تحت قفل الصف عند الحفظ، واختبار نموذج قديم فُتح قبل الاستبدال | نجاح Laravel |

**الأدلة المعتمدة:**
- [Laravel — 2847 assertion و142 warning؛ بلا فشل](https://github.com/5krm/water/actions/runs/43537825760). يتضمن أحدث إصلاح لحماية قراءة API وFilament واختبار النموذج المفتوح.
- [Flutter — 759 PASS و27 SKIP](https://github.com/5krm/water/actions/runs/43536969867)، يتضمن اختبارات العزل في طابور المزامنة.
- [MySQL 8 — نجاح ترحيل السجلات القديمة وعدادين حاليين](https://github.com/5krm/water/actions/runs/43529984017).
- [Laravel — الحذف المالي والصندوق وعمليات bulkDelete](https://github.com/5krm/water/actions/runs/43531066859).
- التعديل الأخير الخاص بتوسيع جمع صور القراءات المرتبطة بالفواتير المحذوفة **لم يتم إثبات نجاحه بواسطة تشغيل CI أحدث مساوٍ لذلك الـCommit عند تحرير هذا التقرير**؛ لا نوسمه مقبولاً حتى تظهر نتيجته.

**تنبيه منهجي:** نجاح اختبار متسلسل يحاكي الإجراء لا يثبت خلو التزامن الحقيقي بين عمليتين متوازيتين على MySQL من كل مشاكل السباق.

## 3. المخاطر المتبقية التي تمنع اعتماد «100%»

1. **قاعدة المستخدم لم تُرحّل:** لا يوجد إثبات تشغيل `migrate` أو `water:audit-single-meter` على قاعدة اختبار متصلة بخادمه؛ متابعة [#39](https://github.com/5krm/water/issues/39).
2. **أجهزة فعلية:** سيناريوهات Android وWindows والطباعة وقطع الشبكة وتزامن الحسابات لم تُنفّذ ميدانياً؛ متابعة [#37](https://github.com/5krm/water/issues/37).
3. **أرشيف ميداني خارج SQLite:** `SharedPreferencesReadingFaultLog` و`SharedPreferencesRouteVisitStore` قد يحتفظان بمعرّفات عدادات محذوفة بعد تنظيف SQLite؛ يجب التخلص من تلك المراجع دون فقد بيانات العدادات الأخرى.
4. **دفعات أعطال وزيارات مختلطة:** `exists:meters,id` على كل صف قبل المعالجة في `ReadingFaultController` و`RouteVisitController` قد يرفض دفعة كاملة عند وجود معرّف عداد محذوف؛ يحتاج رفضاً منفرداً غير قابل لإعادة المحاولة مع نجاح العناصر الأخرى.
5. **MySQL DDL مدمّر وغير ذري بالكامل:** حذف الصفوف داخل معاملة، ثم تعديل المؤشرات/الأعمدة في DDL منفصل؛ يحتاج إيقاف عمليات الكتابة والصيانة وخطة لاستعادة snapshot اختبار عند إخفاق DDL.
6. **اختبار MySQL متزامن فعلي:** حماية `lockForUpdate()` تحتاج اختبار جلستين متزامنتين، لا مجرد نموذج قديم ثم عملية حفظ متسلسلة.
7. **الصور والآثار الخارجية:** حذف صور القراءات عبر `afterCommit` يحتاج اختباراً للملفات الفعلية وفشل التخزين (لا تسترجع MySQL ملفات القرص ضمن معاملتها)؛ كما يجب فحص أي نسخ قديمة مستقلة بشكل منفصل.
8. **تحذيرات ومتجاوزات:** وجود 142 تحذيراً في Laravel و27 اختباراً متجاوزاً في Flutter لا يعني فشل الاختبارات، لكنه يمنع وصف نتائجها بخلو مطلق من الملاحظات.

تُتابع البنود التقنية 3–7 في [#40](https://github.com/5krm/water/issues/40).

## 4. ما الذي عُدّل أثناء هذه المراجعة؟

- منع `SyncQueueManager.discard` من مسح عملية أجنبية، ومنع تعارض `sync_uuid` من إعادة أو استبدال عملية تخص مستخدماً آخر.
- جعل إنشاء قراءة API يعيد التحقق والحفظ تحت قفل صف العداد نفسه المستعمل في الاستبدال، مع إبلاغ عن عداد استُبدل بدلاً من خطأ غير مفهوم إذا اختفى السجل قبل تشكيل الاستجابة.
- أُضيفت المعاملة والقفل نفسيهما إلى الحفظ النهائي في صفحة Filament حتى لو مرّ النموذج بالتحقق المبدئي قبل الاستبدال.
- توسيع جمع صور القراءات المحذوفة من خلال رابط الفاتورة المرتبطة بالعداد القديم في `MeterDataPurger`، وليس `meter_id` وحده.

## 5. قرار إغلاق المراجعة

**المراجعة البرمجية المستقلة أظهرت سلامة عامة جيدة، لكنها كشفت ملاحظات حقيقية. ليس صحيحاً التصريح بـ«100% بلا مشاكل» حالياً.** يُقبل نطاق التعديل الآلي الذي اجتاز CI، وتظل مسائل الصور في أحدث تعديل والقبول الميداني وترحيل قاعدة الاختبار وبقايا SharedPreferences والدفعات الميدانية والتزامن الفعلي مفتوحة. لا يجوز إغلاق #37 أو #39 أو #40 قبل تحقق شروطها وتوثيق الأدلة.

**لا تُشغّل `migrate:fresh` على قاعدة المستخدم، ولا تُطبّق الترحيلات المدمرة قبل التحقق من البيئة والنسخ المرجعية.**
