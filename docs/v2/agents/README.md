# دليل فريق الوكلاء (A1–A10)

هذا الدليل يشرح **من يفعل ماذا** و**كيف يفهم كل وكيل عمل الآخرين**، حتى تُنفَّذ خطة
الإصدار 2.0 بالتوازي دون أن تتصادم الفرق.

- العقد الملزم: `AGENTS.md` في جذر المستودع.
- تعريفات التشغيل: `.claude/agents/water-*.md` (جاهزة لـ Claude Code).
- الحالة الحقيقية: `backlog.json` (39 بطاقة، لكل منها مالك وحالة ودليل).
- الأدوار والمهارات المستوردة: `VENDORED.md`.

---

## 1. لماذا هذا التقسيم؟

الخطة نفسها مقسّمة إلى ست دورات، وكل دورة تمسّ ثلاث طبقات (تطبيق، خادم، جودة).
التقسيم هنا **حسب الملكية** لا حسب الطبقة فقط: وكيل واحد يملك ملفاً واحداً، فلا
يكتب وكيلان في الملف نفسه. هذا هو السبب الأول لفشل الفرق المتوازية.

## 2. الوكلاء وما يجب أن يعرفه كل واحد عن الآخرين

### A1 — قائد الهندسة
- **يفعل**: يوزّع، يراجع، يغلق بوابات S1–S6، يحدّث `backlog.json`.
- **يعرف عن الآخرين**: A2 يوقّع أي مسار جلسة؛ A3 لا يسلم بيئة CI؛ A4+A5 يملكان
  الطابور وقاعدة البيانات؛ A6 يملك كل مسار خادم؛ A7 يستهلك مسارات المال؛ A8 الميدان؛
  A9 النصوص والأنماط؛ A10 لا يغلق بطاقة بلا اختبار.
- **لا يفعل**: لا يكتب كود ميزة؛ تدخله استثناء موثّق.

### A2 — أمن الجلسة والهوية
- **يفعل**: التوكن، التجديد، هوية الجهاز، القفل الحيوي، تعقيم التخزين.
- **يعرف**: A3 يضبط صلاحيات Android وProGuard؛ A4 يحتاج عقد 401؛ A9 يكتب نصوص القفل.
- **مخرجه**: توكن ينتهي ⇒ تحديث صامت ⇒ الطلب ينجح، وجهاز مُبطَل يُرفض فوراً.

### A3 — الإصدار وسلسلة البناء
- **يفعل**: التوقيع، CI، Docker، اختبار التكامل البنيوي، خط أساس التحذيرات.
- **يعرف**: A6 يعطيه أوامر الترحيل والبذر؛ A10 يكتب السيناريوهات وهو يبني المساعدات;
  A2 يخبره بالتبعيات الأمنية.
- **مخرجه**: `docker compose up` يشغّل خادماً ببيانات، و`ci.yml` أخضر.

### A4 — الطابور والمزامنة
- **يفعل**: الأولويات، سياسة الفشل، حالات «يحتاج تدخلاً»، منع التكرار.
- **يعرف**: A5 يوقّع المخطط؛ A2 يعطي عقد 401؛ A7 يعرّف أنواع المال؛ A10 يختبر.
- **مخرجه**: نقدي قبل قراءات، وسند واحد فقط عند فقدان الاستجابة، ولا صف يوقف البقية.

### A5 — البيانات المحلية
- **يفعل**: Drift، الترحيل، التشفير، النسخ الاحتياطي، الفهارس.
- **يعرف**: A4 هو المستهلك الأول؛ A8 يخزّن القراءات والحزمة؛ A10 يختبر الترحيل.
- **مخرجه**: ترحيل بلا فقد، وقرار تشفير مبني على قياس.

### A6 — الخادم وAPI
- **يفعل**: المسارات، الصلاحيات، الفهارس، عقد الأخطاء.
- **يعرف**: A7 يشاركه المال؛ A4 يحتاج رموز أخطاء ثابتة؛ A3 يستهلك أوامر التشغيل؛
  A10 يكتب Feature tests ويحتاج مصانع بيانات.
- **مخرجه**: كل مسار محمي بدليل، وعقد استجابة موحّد بلا كسر التوافق.

### A7 — المال والمساءلة
- **يفعل**: الصندوق، الإلغاء، الاعتماد، تقرير PDF، سجل التدقيق المحلي.
- **يعرف**: A6 يملك المسار؛ A4 يرسل `payment.void` و`cash_session.close`؛ A9 ينسّق
  الأرقام؛ A10 يكتب الحالات الحدّية.
- **مخرجه**: لا سند يُحذف، وكل فرق صندوق مفسَّر، وتقرير يطابق الدفاتر.

### A8 — الميدان والقراءات
- **يفعل**: وضع المسار، التحقق الفوري، الحزمة الأوفلاين، شارة الحالة، قياس الزمن.
- **يعرف**: لا يتحدث مع الشبكة (A4 يفعل)؛ A5 يخزّن؛ A6 يبني حزمة الخادم؛ A9 ينسّق.
- **مخرجه**: 50 قراءة في أقل من 8 دقائق.

### A9 — الواجهة والتوطين
- **يفعل**: الأنماط، RTL، الوصول، استخراج النصوص، شاشة التشخيص.
- **يعرف**: لا يغيّر منطقاً؛ يعرض ما يبنيه A4/A7/A8؛ أي نص جديد يمرّ به.
- **مخرجه**: لا نص عربي مكتوب داخل شاشة، وتباين ولمس مطابقان.

### A10 — الجودة
- **يفعل**: الوحدة، التكامل، اختبارات الفشل، مصفوفة الأجهزة، فرز الأعطال.
- **يعرف**: يطلب من A4 دوالً نقية؛ يأخذ البيئة من A3؛ البيانات من A6؛ الحالات من A7.
- **مخرجه**: لا بطاقة تُغلق بلا اختبار يمرّ أو دليل تشغيل مسجّل.

## 3. دورة العمل اليومية المشتركة

1. A1 يفتح البطاقات ويحدّد المالك من `backlog.json`.
2. المالك ينفّذ **كود + اختبار + توثيق**.
3. A10 يجري الاختبارات ويرفع الدليل.
4. A1 يراجع مع `dependency-guardian` تعارض الملفات ثم يدمج.
5. تحديث `backlog.json` → `sprint-planner` يفتح دورة البطاقات التالية.

### قالب بطاقة مقترح
```json
{"id":"S2-03","agent":"A4","subagent":"queue-engineer",
 "task":"ترتيب الأولويات (نقدي أولاً)","status":"doing",
 "evidence":"test/features/offline_sync/sync_queue_order_test.dart"}
```
