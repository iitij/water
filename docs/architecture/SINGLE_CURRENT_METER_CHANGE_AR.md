# التحويل إلى «مشترك واحد — عداد حالي واحد»

> المرجع السابق محفوظ في [Water_Source_v2026.11.12_PreSingleMeter_806e30f0fded.zip](../../backups/releases/Water_Source_v2026.11.12_PreSingleMeter_806e30f0fded.zip).
> التغييرات الحالية في شيفرة `main`؛ لا يعني ذلك أن ترحيلاً نُفّذ على قاعدة بيانات حية أو أن اختبارات الأجهزة مكتملة.

## القرار التشغيلي

- لكل مشترك **صفر أو عداد حالي واحد**. الصفر مسموح قبل التركيب أو عند الاستبدال.
- العداد الحالي: `removed_at IS NULL AND deleted_at IS NULL`. حالة `status = inactive` لا تلغي ارتباطه.
- العدادات المنزوعة تبقى في التاريخ، وتبقى القراءات والفواتير والسندات والحركات المالية مرتبطة بمعرّفاتها الأصلية.
- نقل ملكية عداد له تاريخ أو مستندات مالية عبر تحرير `subscriber_id` محظور. لا دمج آلي للأرصدة.

## قيد قاعدة البيانات

تضيف الترحيلة `database/migrations/2026_11_12_230000_enforce_one_current_meter_per_subscriber.php` عموداً مولداً `meters.current_subscriber_id`:

```sql
CASE WHEN removed_at IS NULL AND deleted_at IS NULL
THEN subscriber_id ELSE NULL END
```

ثم فهرس UNIQUE باسم `meters_one_current_per_subscriber`. هذا يمنع تكرار العداد الحالي حتى لو أرسِل طلبان بالتزامن أو تم تجاوز واجهة التطبيق، ويترك العدادات التاريخية خارج القيد.

## التحضير الآمن قبل التشغيل

1. نفّذ فحصاً للقراءة فقط على قاعدة البيانات المستهدفة:

   ```bash
   php artisan water:audit-single-meter
   ```

   أو استعلام SQL مكافئ:

   ```sql
   SELECT subscriber_id, COUNT(*) AS current_meters
   FROM meters
   WHERE removed_at IS NULL AND deleted_at IS NULL
   GROUP BY subscriber_id
   HAVING COUNT(*) > 1;
   ```

2. عند وجود تعارض، تحقق من العداد الفعلي، والقراءات غير المفوترة، والفواتير المفتوحة، وسندات القبض ودفتر الأستاذ. لا تختر أول عداد عشوائياً ولا تحذف عداداً ذا تاريخ.
3. إن كان أحد العدادات سابقاً بالفعل، أتم تسوية قراءاته والمعلقات، ووثّق تاريخ النزع الصحيح في `removed_at`؛ وإذا كانت العدادات لوحدات مستقلة، فافصل حسابات المشتركين بقرار محاسبي موثق، دون إعادة إسناد المستندات عشوائياً.
4. أعد تشغيل التدقيق حتى يصل عدد التعارضات إلى صفر.
5. استعد نسخة قاعدة البيانات المتاحة لديك في بيئة منعزلة، وجرّب الترحيل والاختبارات هناك أولاً:

   ```bash
   php artisan migrate --force
   php artisan test --filter='SingleCurrentMeterTest|SubscriberListMetadataTest'
   ```

**الترحيلة ترفض البدء عند وجود تعارض ولا تُعدّل أياً من العدادات لاختيار عداد حالي بديل**.

## إزالة نموذج «المستأجر» من جميع الواجهات

بعد اعتماد المشترك بوصفه صاحب العداد الحالي والحساب، أزيلت حقول `tenant_name` و`tenant_phone`، وخيارات «المشترك/المستأجر» من شاشات Filament وFlutter، والبحث والنماذج وإعدادات الفاتورة والسند وملفات PDF وExcel وقنوات واتساب. يعتمد عرض المستلم وإرسال الفاتورة والسند على اسم المشترك ورقم هاتفه فقط.

- قاعدة MySQL/SQLite: الترحيلة `database/migrations/2026_11_13_220000_drop_tenant_identity_from_meters.php` تُسقط العمودين من جدول العدادات، وتحتفظ بمعرّفات العدادات ومراجع القراءات والفواتير والحركات السابقة. لا تنقل بيانات المستأجر القديمة إلى المشترك؛ بيانات التطوير الحالية تجريبية.
- قاعدة Flutter المحلية: لا تُنشئ حقلي مستأجر في جدول `cached_meters` الجديد، ولا تستخدمهما في التخزين المؤقت أو البحث. القواعد القديمة التي أُنشئت على أجهزة سابقة قد تحتفظ بأعمدة غير مستخدمة حتى إعادة تهيئة التخزين المحلي.
- عمليات الاستبدال: يبقى `Subscriber::meters()` للعلاقات التاريخية؛ لا يعني ذلك السماح بعدادين حاليين. يُستخدم `currentMeter()` في العمل اليومي.
- الحماية من الرجوع: [فحص غياب المستأجر من الشيفرة النشطة](../../.github/workflows/audit-legacy-meter-ui.yml) يفشل عند ظهور تلك الحقول أو التسمية في `app/` أو `resources/views/` أو `mobile app/lib/`.
- القبول الميداني على أجهزة حقيقية يبقى في [#37](https://github.com/5krm/water/issues/37) ولا يُستنتج من CI.

## إعادة تهيئة البيانات التجريبية والتحقق على MySQL

لأن البيانات الحالية تجريبية، يمكن التخلص منها **في قاعدة اختبار مخصصة فقط** باستخدام:

```bash
# تأكد أولاً أن DB_DATABASE يشير لقاعدة تجريبية، وليس قاعدة الإنتاج.
php artisan migrate:fresh --seed
php artisan water:audit-single-meter
```

هذا أمر مدمر لجميع بيانات قاعدة البيانات المحددة؛ لا تشغله على خادم إنتاج ولا على قاعدة يراد الحفاظ عليها.

اختبار GitHub Actions الآلي [MySQL single-meter compatibility](../../.github/workflows/mysql-single-meter-check.yml) يشغّل `migrate:fresh` ضد حاوية MySQL 8 مؤقتة مخصصة للاختبارات، ويتحقق من أن فهرس UNIQUE المولد يمنع العداد الثاني، ويسمح بعداد تاريخي وبديل حالي، ويمنع إعادة تفعيل القديم ما دام البديل قائماً. لا يتصل هذا الاختبار بأي قاعدة تشغيلية.

## الحدود

- لم يُجرَ فحص على قاعدة التشغيل الحية، ولا تغيير لأرصدتها.
- الاستبدال أصبح ذرياً وله سجل تدقيق. يتطلب تأكيد آخر قراءة وفوترتها قبل الاستبدال؛ القراءات المؤجلة التي تصل بعده تُرفض وتحتاج مراجعة بشرية. اختبارات الأجهزة الفعلية ما زالت مطلوبة قبل الإنتاج.
- تبقى أمانة بيانات المال أولوية؛ يظل الرصيد العام ورصيد كل عداد منفصلين في دفتر الأستاذ الحالي.
- نجاح اختبارات PHP لا يثبت اختبارات Flutter على أجهزة حقيقية أو كل جوانب الإنتاج.
