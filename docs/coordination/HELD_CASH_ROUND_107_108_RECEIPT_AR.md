## قرار تصميم تحرير السيولة — مسودة مراجعة غير مفعلة

### القاعدة المحاسبية
لا تُعد التسوية الدائنة على حساب المشترك قبضاً جديداً. لا يحرر مجرد تخصيص الدائن لفاتورة النقد المحتجز، لأن إلغاء الفاتورة وتصحيحها وإعادة توزيع المدفوعات قد يعيد الدائن غير المخصص. إغلاق فترة مستند الفاتورة وحده غير كافٍ: خوارزمية إعادة التخصيص تقرأ الفواتير النشطة ومصادرها على مستوى المشترك وتعيد الحساب عبر الفترات.

لكل حساب خزينة نقدية، بالوحدات الصغرى الصحيحة:
- H: مجموع الالتزامات غير المصروفة وغير المحولة إلى رصيد مشترك.
- C: مجموع الدائن الناتج عن الفائض، سواء كان مخصصاً أو غير مخصص.
- A: الجزء المخصص المثبت حالياً من C؛ U = C - A.
- P: الاستردادات النقدية المثبتة غير المرحلة على مستوى القناة، احتياطياً دون اختلاق نسبة لحساب بعينه.
- B: رصيد نقد مسجل مستند إلى مصادر متطابقة، وليس جرداً نقدياً معتمداً.
- R: مبلغ محرر بموجب آلية معتمدة مستقبلاً، مع 0 <= R <= A <= C.
- الحماية الحالية H + C، والهامش المتاح حسابياً B - P - H - C. لا يجوز استخدام الهامش السالب كقدرة صرف.
- الحماية المقترحة H + C - R. قبل أي تحرير أو صرف يجب إثبات B - P >= H + C - R + المبلغ المطلوب. عند أي إعادة تخصيص ترفع U يجب خفض R بما يكفي في المعاملة نفسها. إن تعذر توفير الغطاء، تُرفض العملية الاختيارية قبل التنفيذ، أو يلزم تمويل مثبت. أما خسارة أو صرف حدث بالفعل فيجب تسجيله كواقعة مع إظهار العجز ومنع الصرف الإضافي، لا محو الواقعة لمجرد نقص السيولة.
- إجمالي R لا يزيد أبداً على مجموع مبالغ المصادر المؤهلة فعلاً، ولا يجوز احتساب نفس التخصيص مرتين أو جمع P عبر حسابات مختلفة.

### متطلبات التفعيل الصريحة
1. حصر جميع نقاط الكتابة المغيرة للتخصيص والسيولة، بما فيها واجهات API وFilament والمهام والخدمات وإعادة التشغيل، والمسارات المباشرة إلى قاعدة البيانات.
2. ترتيب قفل واحد لكل الكتاب: النطاق والفترات عند الحاجة ثم قفل الإصدار ثم حسابات الخزينة مرتبة ثم المشتركين مرتبين ثم المستندات. لا يتم الحصول على قفل النطاق بعد قفل عمل. يجب فحص الخدمات التي تبدأ بالمشترك قبل الإصدار، ومنها PaymentRefundService وPaymentService، وفحص الاستدعاءات المتداخلة.
3. تثبيت حد فاصل واضح لاحتساب R، ومستند تحرير مستقل، يربط مصدر الدائن والمبلغ والحساب والمشترك ومراجعة التخصيص وتجزئة الأدلة والفترة وهوية الموافق وتاريخ العملية. سجل إضافي لا يقبل التعديل أو الحذف. عكس التحرير مستند منفصل.
4. حصر الاستثناءات: تحرير جزئي، تغير التخصيص من فاتورة إلى أخرى، إلغاء أو تخفيض فاتورة، استرداد أو إلغاء سند، نقل بين المشتركين، تصحيح تاريخي، قراءة مكررة، عمليات متزامنة. لا يكفي التحقق من رصيد المشترك الإجمالي.
5. إثبات ذري لجميع التغييرات: التخصيص والقيد والمستند والتدقيق وتغير R وفحص السيولة في معاملة واحدة. لا تُطلق حركة نقدية عند التحرير المحاسبي وحده.
6. التحقق المستقل من اكتمال مصادر الخزينة والسجل، واختبارات MySQL المتزامنة مع SQLite للاختبارات الحتمية، وإثبات عدم تأثير القيود الجديدة على تسجيل الخسائر الفعلية.
7. عدم منح واجهة عامة أو تفعيل إنتاجي أو دمج قبل تفويض مستقل.
