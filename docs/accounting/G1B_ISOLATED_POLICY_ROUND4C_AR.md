## 2. عقد المحرك
- open(scope, month, timezone): إنشاء candidate فقط، ليس أمر فتح دائم؛ لا يستعلم عن فترات أخرى. strict YYYY-MM (1000-01..9999-11)، IANA explicit timezone، first day وnext month exclusive، version=0، null attempt/closure. Asia/Aden مستخدمة في الاختبار كمقترح محاسبي؛ UTC issuance calendar منفصل. اختبارات لحظة 2026-11-30 21:00Z = 2026-12-01 00:00+03 وleap month. التقويم النهائي وتاريخ الافتتاح يعتمدهما المشرف.
- assertCanPost: حالة OPEN فقط، scope fence غير مفعّل، تاريخ effective_on داخل الفترة ولا يتجاوز اليوم المحاسبي، رفض غياب الفترة، scope مختلف، authorization/state/actor/gate غير مثبتة. لا يستدعي DB، لا يدعي حماية الكتّاب الحاليين. يجب أخذ gate الحقيقي قبل استدعاء السياسة وعدم إفلاته حتى commit.
- freeze: OPEN -> FROZEN بعد انتهاء الشهر، predecessor_verified+writers_drained، request UUID غير مستخدم، reason (10..2000 bytes UTF-8, trimmed)، actor، gate epoch+1، version+1، hash predecessor/baseline. لا إعادة فتح CLOSED؛ لا freeze مبكر. prepare: يبقى FROZEN، same UUID/epoch/version، actor وتوقيت لا يسبق freeze، تجهيز واحد فقط. تحقق immutable snapshot canonical hash. approve: FROZEN+prepared -> CLOSED، actor مستقل عن requester/preparer، UUID اعتماد مستقل، current reverified snapshot/hash/manifest/predecessor، monotonic UTC timestamp، version increment/release_epoch+1. يحتفظ snapshot وبيانات الاعتماد وبصمة closure. Exact approval replay (نفس UUID, attempt, actor, version, snapshot hash, scope/month/timezone, validated persisted effects) يرجع الحالة نفسها بلا تغيير؛ أي اختلاف رفض. لا يدعم replay مستقل لكل freeze/prepare/abort في هذه الشريحة؛ adapter عليه durable request registry لإعادة الرد أو رفض التعارض، قبل أي transition. abort: FROZEN -> OPEN فقط قبل الاعتماد وبصاحب قرار مستقل، reason وUUID، epoch/version متزايدان، يحتفظ attempt وsnapshot في aborted history. لا CLOSED -> OPEN.
- context facts هي حقائق يثبتها محول خادم موثوق تحت الأقفال وليست payload للمستخدم: gate_held/state_verified/scope/authorized operation/actor_active/actor/epoch/scope_fenced، ومفاتيح العملية/predecessor/drain/coverage/manifest/snapshot/carry evidence. لا ترسل flags من API. الكود يفحص شكل الحالة الأساسية ولا يثبت أصالة أي array أو يحقق هوية المستخدم فعليًا؛ أي استدعاء مباشر ليس تفويضًا. open لا يخلق سجلًا ولا يمكن استخدامه لتبديل CLOSED؛ persistence adapter يجب أن يمنع تكرار scope/month ويطبق predecessor/overlap/gap rules.
- snapshot v1: 8 sectors mandatory coverage flags + trusted complete source manifest، rows لكل sector/key unique، source_hash لكل row، opening+movement=closing exact. subscriber/bank signed؛ بقية أرصدة opening/closing غير سالبة. allocation row closing=allocated+surplus exact، caps/source-level detailed proof ضمن manifest. يحسب debt/credit منفصلين لكل subscriber row، لا netting بين المشتركين. يحمل canonical ordered row data/carry/sector totals وpredecessor/source manifest hash، وليس مجرد hash. Money output canonical integer strings (wire-safe)، no float. يجب حفظ canonical serialization أو إعادة ترطيبه بشكل متطابق قبل hash، لا الاعتماد على JSON object key order من DB. SHA256 دليل سلامة للتمثيل لا توقيع أو حماية صلاحيات.
- carry: transit/custody/liability/recoverable فقط في الشريحة الأولى، positive amount، unique id، existing sector row، مسؤول مثبت ومهلة لا تسبق الفترة التالية ودليل hash؛ مجموع كل carry يساوي closing row بالكامل. لا carry لفرق نقدي/بنكي مجهول، ولا pending noncash claim كرصد مالي. due_on فحص عند cut-off؛ aging عند يوم الاعتماد/تأخر المحاولة والسياسة المتفق عليها يحتاج تحقق adapter. لا resolution أو carry-forward فعلي الآن؛ يلزم التحقق من opening القادم ومصدر المطالبة وربط resolution مرة واحدة. Bank signed negatives تحتاج overdraft verified، لا يثبت المحرك حق البنك أو صحة المصدر. Raw source coverage/empty-sector evidence/row IDs/debit match/cap/reconciliation proofs تُستخرج من محول موثوق، no_unexplained_variance ليست بديلًا عن المطابقة.
- جميع الدوال تنتج قيم arrays جديدة بلا آثار جانبية. domain errors ثابتة، لا persistence، لا audit append حقيقي، لا استعلام أو قفل أو network. state returned من السياسة لا يصبح durable إلا بمعاملة معتمدة تجمع snapshot, state/epoch CAS, immutable effects, audit, request result. فشل أي جزء rollback؛ لا فتح تلقائي ولا تكرار إقفال. OPEN/FROZEN/CLOSED نهائية في عقد التخزين المستقبلي؛ DB constraints/roles/guards/backup chain مسؤولية G1B integration.
