## دورة الحالة والآثار
| الحالة الحالية | الحدث المثبت | الحالة التالية | ائتمان المشترك | حركة البنك |
|---|---|---|---:|---:|
| pending | رفض قبل تحقق الأموال | rejected | 0 | 0 |
| pending | تحقق الإيداع الكامل (المسار الحالي) | cleared | +M | +M |
| cleared | خصم بنكي كامل مثبت | returned | -M | -M |
| returned / rejected | إعادة تقديم مصرح بها | محاولة pending جديدة | 0 | 0 |
| pending الجديدة | تحقق جديد | cleared | +M | +M |
الآثار بواحدات minor صحيحة، وإشارة دفتر المشترك الحالية موجبة للقبض وسالبة للعكس. مثال فاتورة 10000 minor: بعد قبض 10000 الدين صفر، بعد ارتجاع كامل يعود الدين 10000. القيد الأصلي والمطابقة الأصلية لا يحذفان. لا رسوم تلقائية على المشترك، لا refund نقدي أو void عادي، ولا تعديل لصندوق مغلق. إعادة التقديم والتصفية الجزئية والتجميع والحالات المركبة ليست جزءا منفذا من هذه الدفعة.

## عقد الخوارزمية المعزولة
- الدالة planUnclearedRejection تتطلب طلب شيك pending بلا سند أو أثر مالي، مبلغ صحيح موجب، تاريخ رفض بين تاريخ الأداة وتاريخ العمل، اعتماد مستقل ومصرح وإثبات رفض موثق (rejection_proof_valid)، هوية طلب ومرجع ودليل. ترجع خطة رفض دون قيود أو إنشاء سند. إعادة الطلب قبل التحصيل تحفظ في محول التكامل اللاحق تحت قيد فريد؛ هذه الدالة لا تخزن حالة.
- planFullReturn تستقبل original + debit + decision + state + asOf. جميع الحقول المالية int فقط، لا float أو numeric-string أو تقريب، لا تجزئة ولا مقاصة رسوم. original: هوية سند ومشترك وإثبات التحصيل والحساب وسطر الإيداع والمبلغ والأداة ومنشئ السند وتاريخ التحقق وصحة الإثبات التاريخي وعدم ربط صندوق. debit: هوية سطر مستقل، نفس الحساب، اتجاه سالب ومبلغ -M حرفيا، تاريخ لا يسبق التحقق ولا يتجاوز asOf، بصمة كشف سليمة ومدخل كشف ومرجع بنكي، وربط مثبت بالتحصيل والأداة الأصلية (return_link_verified, linked_collection_id, linked_instrument_reference). تطابق المبلغ وحده لا يثبت الهوية. decision: UUID قانوني lowercase، مرجع ودليل غير فارغين، طالب ومعتمد مختلفان، المعتمد ليس منشئ السند ولا مدخل الكشف وله صلاحية. asOf يوم العمل المحاسبي من عقد التوقيت، لا استدعاء now داخل المنطق.
- state: line_consumed/reference_consumed/request_uuid_consumed/payment_reversed/period_open/has_refund/has_account_transfer/has_other_correction/has_pending_void كلها bool صريحة؛ existing_plan إما null أو الخطة المحفوظة، existing_effects_valid مطلوب عند replay. رفض إذا إثبات تالف، اختلاف الحساب أو السطر أو التاريخ أو المبلغ، اعتماد ذاتي، استهلاك سابق، فترة مغلقة، سند مع استرداد أو نقل أو تصحيح أو طلب إلغاء معلق. لا طرح قيم متغيرة قد تتجاوز حدود int؛ عكس مبلغ موجب واحد حتى PHP_INT_MAX.
- ترجع planned + خطة ثابتة تحمل معرفات المصدر والإثبات والقرار وآثار -M/-M وتطلب إعادة تخصيص الفواتير. replay فقط إن طابقت الخطة الأصلية المحفوظة بالكامل مع تحقق استهلاك المرجع والسطر وUUID والعكس وأثرهما الفعلي؛ لا كتابة في replay ولو أغلقت الفترة. تغير البيانات أو تضارب UUID/مرجع/سطر/سند => رفض. DomainException برمز مستقر للرفض، وليس نجاحا ماليا. الطلب المعزول لا يقرأ قاعدة البيانات أو صلاحية المستخدم فعليا؛ flags وexisting_plan حقائق موثوقة يستخرجها المحول من السجلات وليس من عميل API.

## تكامل لاحق مشروط (غير منفذ)
تحتاج قاعدة البيانات مستند ارتجاع ثابت FK RESTRICT إلى التحصيل والسند وسطر الخصم، unique على payment_id/collection_id/return_line_id/request_uuid/reference (في نطاق كامل العكس الأول)، إثبات تاريخي غير قابل للحذف، وقيد خزينة سالب ومطابقة خصم وعكس دفتر المشترك مستقل وإعادة تخصيص الفواتير وتدقيق في معاملة واحدة. يتم التحقق من البصمة وهوية السند والقرار والمبلغ وقيود الأدوار وبيانات الإقفال تحت الأقفال، لا اعتماد bool يرسله العميل. ترتيب الأقفال المقترح: subscriber ثم issuance ثم payment/return provenance ثم bank statement/account/line؛ يجب مراجعة جميع المسارات المتداخلة وdeadlock retry مع B قبل الدمج. إعادة الطلب تبحث عن تضارب أي مفتاح فريد وتعيد نتيجة محفوظة فقط بعد التحقق من جميع الآثار؛ لا تسجل قيدا آخر. يمنع أثر مكرر في حال التزامن عبر قفل المصدر وقيود فريدة وقاعدة ذرية، لا يثبت هذا الاختبار المعزول ذلك.
فصل صلاحية إثبات الإيداع التاريخي عن صلاحية سند حالي معكوس؛ eligibleCollection حاليا يرفض المعكوس، فلا يجوز إعادة استعماله كاختبار لصحة إثبات قديم بعد الارتجاع. إعادة تقديم الشيك تستلزم هوية instrument ثابتة ومحاولات مرتبطة (unique الحالي يمنع إعادة تقديمه)، محاولة نشطة واحدة، إعادة تقديم بعد رفض/ارتجاع مثبت فقط. لا تغيير رقم الشيك للتحايل. حالات refund/transfer/partial/legacy cash session تبقى استثناءات غير مسواة حتى عقد موثق؛ لا إخفاء خصم البنك أو شهادة رصيد.
اعتماد ACC-09 exact money وACC-14 أرقام المستندات وACC-10 FK/provenance؛ تصميم G1B للإقفال والحماية. PaymentService/TransactionService/BankReconciliationService/TreasuryRegisterService/FinancialReconciliationService/models/routes/Flutter/Filament مجمدة. لا migration أو تغيير في ملفات موجودة أو بيانات فعلية.
