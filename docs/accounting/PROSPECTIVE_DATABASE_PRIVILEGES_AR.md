# فصل صلاحيات قاعدة البيانات قبل الإنتاج

## الغرض
يُنفّذ النشر والترحيلات بحساب نشر مستقل، ويستخدم التطبيق حساب تشغيل محدوداً. لا يُحفظ اعتماد النشر في إعدادات الموقع الدائمة. لا تُمنح حسابات التشغيل صلاحيات DDL أو TRIGGER أو GRANT OPTION أو صلاحيات عامة أو أدوار غير مراجعة.

## التحقق
- بحساب النشر، نفّذ `php artisan ledger:protect --install` بعد الترحيلات عند الحاجة، ثم `php artisan financial:database-preflight --guards`. يفحص الأمر الحواجز المحددة دون تثبيتها أو تعديل البيانات.
- بعد تهيئة إعدادات التشغيل الفعلية وإعادة تحميل إعدادات Laravel، نفّذ `php artisan financial:database-preflight --runtime`. يفحص الأمر SHOW GRANTS لاتصال الكتابة الفعلي، ولا يطبع الاعتمادات أو نصوص المنح.
- امنح SELECT/INSERT/UPDATE/DELETE حسب حاجة التطبيق فقط وعلى قاعدة الموقع وحدها. يُفضّل تحديد الجداول صراحة. أسماء قواعد البيانات التي تحتوي على "_" تحتاج ضبط المنح بحيث لا يتحول الاسم إلى نمط مطابق لقواعد أخرى؛ يرفض الفحص المنح العامة أو غير المفهومة. لا يُعد نجاح الفحص إثباتاً لاكتمال الصلاحيات اللازمة لكل واجهة.
- لا تُمنح TRIGGER لحساب التشغيل لمجرد إظهار information_schema.TRIGGERS. صلاحية إنشاء/إسقاط الحواجز منافية للفصل. بعض خدمات فحص الحماية الحالية تعتمد على رؤية بيانات الحواجز في وقت التشغيل؛ يلزم حل تلك التبعية واختبارها بحساب محدود قبل اعتماد الإنتاج. لا تتجاوزها بمنح صلاحيات مرتفعة.

## حدود الثقة
حساب يملك INSERT على جدول مالي يستطيع إصدار SQL مباشرة من خارج التطبيق. الحواجز الحالية تتحقق من بعض البنية والأدلة، لكنها لا تثبت هوية خدمة PHP أمام قاعدة البيانات المشتركة. منع تزوير الأدلة يتطلب حدود صلاحيات دقيقة أو مسار كتابة مستقل، واختبارات للحساب المحدود؛ لا يكفي فحص المنح أو أسماء Triggers. نجاح الفحص لا يجيز تشغيل الإنتاج أو الإغلاق المحاسبي. لا تغييرات في البيانات التاريخية أو الأرصدة الافتتاحية.

## قراءة تعريفات الحواجز للحساب المحدود
فشل العرض SQL SECURITY DEFINER في اختبار الحساب المحدود على MySQL 8. استُبدل في المرشح غير المنشور بإجراء ثابت بلا مدخلات باسم financial_read_trigger_metadata، للقراءة فقط، وبصلاحية EXECUTE على هذا الإجراء وحده. يتطلب حساب النشر CREATE ROUTINE وصلاحية الاطلاع على الحواجز. لا تمنح EXECUTE عاماً أو TRIGGER لحساب التشغيل. افحص بحساب النشر أولاً، ثم اضبط FINANCIAL_TRIGGER_METADATA_ROUTINE=true لحساب التشغيل واختبر --runtime و--guards. لا يوجد رجوع صامت إلى مصدر آخر. نجاح الإجراء في CI لا يثبت توافق Namecheap؛ إذا تعذر إنشاؤه على الاستضافة يبقى الاعتماد معلقاً. لا يمنع هذا تزوير DML بواسطة اعتماد كتابة مخترق.
