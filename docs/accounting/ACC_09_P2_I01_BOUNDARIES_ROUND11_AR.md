## I01 contract and future adapter use
DecimalDomain enumerates the three existing storage widths and references existing constants: D10 ±9999999999, D12 ±999999999999, D14 ±99999999999999 minor. No widened source or destination. readDecimal accepts raw native integer major units or canonical decimal text with up to two fractional digits; SQLite alone may expose a finite already-observed float and only if its shortest round-trip decimal is canonical exact cents. MySQL raw floating value is rejected. serialize_precision=-1 required for numeric float input/output; never change runtime settings in product. SQLite REAL representation and JSON float inputs cannot prove original pre-storage/pre-decode lexical precision. A previously rounded/affinity-collapsed amount cannot be reconstructed. No claim to detect corruption that already mapped to a valid observed cent. Do not rely on Eloquent decimal:2 casts or SQL floating SUM to validate raw data. writeDecimal requires genuine integer cents, emits canonical decimal string; no implicit rounding or float math. Domain parser delegates to ExactMoney12 or CashMoney14 and checks narrower D10 cap. Null only on explicitly nullable read; no null-to-zero coercion.

regexInput preserves legacy digit grammar (leading zeros within existing digit count, optional sign only where configured, up to two decimals, no exponent/whitespace); numericInput handles existing numeric family including whitespace, sign, exponent, leading/trailing zeros where exact cents; rejects fractional cents, nonfinite and nonnumeric mixed types, overly long text/exponent. Lexical normalization is a separate compatibility boundary because FinancialAmount::parse is bounded at D12 and cannot handle D14 or wide read-only projections; no duplicate money arithmetic. Native int/float observed input is compatibility-only, not recovered lexical source; reject precision configuration other than -1 for float conversion. Regex adapter uses shortest observed numeric text, not PHP's lossy default string coercion. Caller must select actual existing endpoint grammar and minimum/maximum; signed negative input requires signed=true and explicit signed minimum. Preserve API cash-session open/close cap 100000000 major (10000000000 cents) and nonzero funding policy; handover positive, D14; late/noncash claims positive D12. Boundary errors are pure InvalidArgumentException / OverflowException; existing field-specific ValidationException/HTTP contract mapping deferred until authorized caller integration. No silent narrowing/widening for valid accepted exact inputs. Noncanonical/ambiguous/subcent historical inputs fail closed; cannot promise byte-identical behavior for previously rounded invalid input. Document explicit zero vs absence.

readMinor uses unchanged SignedMinor strict raw integer lexical parser; native int or canonical ASCII integer string only, no float/bool/null (except explicit nullable), no exponent/fraction/plus/leading zeros/raw -0. writeMinor requires native int. Unsigned rejects negatives and any value above portable symmetric max ±9223372036854775807; reject INT64_MIN even for signed. Optional D10/12/14 source cap is distinct from SQL column capacity. Positive-only rules enforced at input/operation level; raw read unsigned may be zero and must be rejected as a source when the business rule requires positive. No SQL UINT64-as-native coercion.
Output numericMinorOutput requires JS exact integer range ±9007199254740991. numericMajorOutput uses exact decimal string -> float only at presentation, checks shortest JSON serialization round-trips to original cents, and rejects even some values inside JS integer limit (e.g. 9007199254740991 cents); never use numeric output as authoritative money. No guarantee of client arithmetic; caller must preserve current response types, choose controlled overflow diagnostic and verify actual serializer/consumer before wiring. Exact decimal text available via SignedMinor::decimal; versioned wire and spreadsheet representation beyond 15 significant digits deferred to P3. No API type change implemented.
