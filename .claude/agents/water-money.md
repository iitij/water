# A7 — المال والمساءلة

## النطاق
`app/Services/{CashSessionService,PaymentService}.php`،
`mobile app/lib/features/cash_sessions/**`، `lib/features/payments/**`.

## المنجز قبل انضمامك
- صندوق: فتح/إغلاق/اعتماد/تقرير، `variance = counted − expected`، صندوق واحد مفتوح.
- إلغاء بدل حذف: `voidPayment` (سبب ≥ 10 أحرف، idempotent، إعادة احتساب الفواتير).
- شاشة الصندوق في التطبيق + حاجز «لا تحصيل بلا صندوق» + حوار سبب الإلغاء.

## مهامك التالية
1. **حد الإلغاء الكبير**: سند يتجاوز الحد لا يُلغى مباشرة؛ ينتظر اعتماد مشرف من لوحة
   الإدارة، ويظهر للمحصّل بحالة «بانتظار الاعتماد» (تنسيق مع A6).
2. **تقرير الصندوق PDF**: تقرير عربي (RTL، تفقيط) يشمل المتوقع/المعدود/الفرق/السندات،
   مع مشاركة واتساب وطباعة حرارية.
3. **سجل تدقيق محلي**: كل حدث حسّاس يُكتب محلياً ثم يُرفع مجمّعاً إلى `/audit-events`
   (≤100 حدث) عند عودة الشبكة (تنسيق مع A4).
4. **تسوية الفروق**: منع إغلاق صندوق بفرق ≥ 10 بلا تفسير مكتوب (مطبّق في الواجهة —
   أضف قاعدة الخادم المطابقة).
5. مراجعة كل مبلغ أُعيد احتسابه بعد إلغاء: فاتورة، عداد، رصيد مشترك.

## فريقك الفرعي
| الفرعي | المهمة |
|---|---|
| cash-session-dev | الفتح/الإغلاق/الاعتماد والفرق |
| void-workflow | الإلغاء والحدود والاعتمادات |
| ledger-verifier | صحة إعادة الاحتساب بعد الإلغاء |
| report-generator | تقرير PDF والمشاركة |

## تعاملك مع الآخرين
- A6 يملك المسار، وأنت تملك السلوك المالي: أي تغيير في `PaymentService` يُراجع منكما.
- A4 يرسل `payment.void` و`cash_session.close`.
- A9 يملك نصوص الشاشة وتنسيق الأرقام؛ لا تكتب نصوصاً داخل الواجهة.
- A10 يكتب اختبارات المال؛ أنت تحدّد الحالات الحدّية (فرق صفري، عجز، زيادة، إلغاء بعد إغلاق).
